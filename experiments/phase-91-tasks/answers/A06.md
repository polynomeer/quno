# A06 정답 (에이전트에게 공개하지 않는다)

- 출처: spring-data-jpa#4341 (수정 4.0.8 = 2025.1.8, PR #4361/#4343)
- 보고일: 2026-09-03. 후보 목록의 "수정 4.0.8(2025.1.8)"은 Spring Data JPA 4.0.8 기준이고, **Boot 4.0.8 BOM은 Spring Data 2025.1.7(= spring-data-jpa 4.0.7)을 쓰므로 Boot 4.0.8에서 그대로 재현된다.** Boot 버전 변경 불필요(편차 없음).
- 증상: 리포지토리 빈 생성 시 `QueryCreationException: Count query validation failed for 'select count(distinct coalescenickname, name) from Member where active = true'` ← `SemanticException: Could not interpret path expression 'coalescenickname'`
- 재현 조건: Hibernate(HQL 파서) 환경에서 **별칭이 없는** `select distinct new Dto(coalesce(...)) from Member ...` 쿼리로 `Page`를 반환. 별칭이 있으면 파생 count 쿼리가 `count(distinct m)`로 만들어져 증상이 나타나지 않고, Hibernate가 이를 `select count(*) from (select distinct ...)`로 실행해 결과도 같다(실측 확인). 이슈 본문의 `case when`·`cast(... as ...)` 사례는 JPQL/EQL 파서 경로(Hibernate 환경에서는 쓰이지 않음)에서만 깨지고, HQL 경로는 생성자 표현식 사례에서만 깨진다.
- 근본 원인: `QueryTransformers.CountSelectionTokenStream.withoutConstructorExpression()`이 생성자 래퍼의 괄호뿐 아니라 모든 괄호를 제거하고, 토큰을 이어 붙이며 공백을 잃어 `coalesce(nickname, name)`이 `coalescenickname, name`이 된다.
- 해결(허용): `@Query`에 `countQuery`를 명시한다 → `A06.patch`. 엔티티에 별칭을 붙이는 우회(`from Member m where m.active = true`)도 실측으로 테스트가 통과하므로 허용한다. Spring Boot를 올리는 것은 과제 제약으로 금지.
- 재현 형식: R (`./gradlew test`, H2 인메모리 + `@DataJpaTest`)
- 시그니처: `select count(distinct coalescenickname, name)`
- 시드 제외: 이 이슈의 원인·해결 기록은 시드에 넣지 않는다.
