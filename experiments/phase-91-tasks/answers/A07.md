# A07 정답 (에이전트에게 공개하지 않는다)

- 출처: spring-boot#52121 (수정 PR, 수정 4.0.9)
- 보고일: 2026-10-09 (Boot 4.0.8에서 확인됨, 수정 PR 병합 10-12)
- 증상: `spring.mongodb.password=my secret`이 드라이버에 `my+secret`으로 전달됨 — `expected: "my secret" but was: "my+secret"`. 실제 환경에서는 인증 실패.
- 근본 원인: `PropertiesMongoConnectionDetails`가 사용자 이름·비밀번호를 `URLEncoder.encode`로 URI 인코딩하는데, 이 인코더는 공백을 `+`로 바꾼다. MongoDB 드라이버의 `ConnectionString`은 `+`를 리터럴 `+`로 해석하므로 공백이 `+`로 바뀐다.
- 해결(허용): 별도의 `username`/`password` 프로퍼티 대신 `spring.mongodb.uri`에 공백을 `%20`으로 직접 인코딩해 넣는다 → `A07.patch`. 직접 `MongoConnectionDetails` 빈을 정의해 `%20`으로 인코딩하는 것도 허용. 비밀번호 자체를 바꾸는 것(공백 제거)은 제약 위반. Boot 4.0.9로 올리는 것도 금지.
- 재현 형식: R (`./gradlew test`, 서버 불필요 — `MongoConnectionDetails`가 파싱한 자격 증명을 검사). D가 아니다.
- 시그니처: `but was: "my+secret"`
- 시드 제외: 이 이슈의 원인·해결 기록은 시드에 넣지 않는다.
