## 채점 기준

- 원인(2점): Kotlin(KGP)이 JVM 25 타깃을 지원하지 않아 24로 폴백하고, 그 결과 Java 25 / Kotlin 24 타깃 불일치 경고가 난다. (경고 출처를 Gradle 자체 버그로 단정하면 0점)
- 해결(2점): 툴체인을 KGP가 지원하는 JDK(24/21)로 맞춘다 **또는** JVM 25 지원 Kotlin(2.3+)/그것을 내장한 Gradle로 올린다. 무시 가능(빌드 성공)이라고 짚으면 가산 없이 허용.
- 감점(-1): 빌드 실패의 원인을 찾으려는 방향(JAVA_HOME, 캐시 삭제 등)으로 확정.
- 상태: 이슈 gradle#35204 (2025-10-02)의 메인테이너·기여자 설명과 일치. 어느 Gradle 버전부터 해소되는지는 이슈 내에서도 논쟁이 있어 채점하지 않는다.

## 참고 진단서 (answers/B09.patch가 DIAGNOSIS.md로 추가함)

## 원인

경고는 Gradle이 아니라 Kotlin Gradle 플러그인(KGP)에서 나온다. `build-logic`이 사용하는 `kotlin-dsl`에 내장된 Kotlin 버전은 JVM 25 바이트코드 타깃을 지원하지 않아, 컴파일 대상을 JVM 24로 낮춘다("falling back to Kotlin JVM_24"). 그 결과 Java 컴파일(25)과 Kotlin 컴파일(24)의 타깃이 달라져 "Inconsistent JVM Target Compatibility" 진단이 나온다. 빌드는 성공한다. 문구의 "Gradle 8.0에서 에러가 된다"는 오래된 템플릿 문구라 현재 동작과 무관하다.

## 해결

1. Java와 Kotlin 컴파일이 같은 타깃을 쓰도록, KGP가 지원하는 JDK(24 또는 21)로 JVM toolchain을 맞춘다.
2. JVM 25 타깃을 지원하는 Kotlin(2.3.0 이상)을 쓰고, 내장 Kotlin이 그 버전인 Gradle(9.3 이상으로 논의됨)로 올리거나 `kotlin-dsl` 대신 `org.jetbrains.kotlin.jvm`을 직접 쓴다.
3. 당장 영향이 없으므로 무시해도 된다.

## 근거

확신: 경고 출처가 KGP이고 타깃 불일치(25 vs 24)가 직접 원인이라는 점. 추정: 어느 Gradle 버전부터 내장 Kotlin이 JVM 25를 지원하는지(논의에서 의견이 갈림).
