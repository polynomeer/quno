# B03 정답 (에이전트에게 공개하지 않는다)

- 출처: spring-boot#48880 (수정 4.0.2, `type: regression`)
- 보고일: 2026-01-19 (Boot 4.0.1에서 확인됨)
- 증상: `IllegalStateException: No transaction is in process; possible solutions: ...` — `@Transactional` 메서드 안에서 `KafkaTemplate.send`를 호출했지만 트랜잭션이 시작되지 않는다. 에러 없이 `@Transactional`이 무시된다.
- 근본 원인: Boot 4.0 모듈화로 `TransactionAutoConfiguration`(자동 `@EnableTransactionManagement` 포함)이 `spring-boot-transaction` 모듈로 분리되었는데, `spring-boot-starter-kafka`(→ `spring-boot-kafka`)가 이 모듈을 가져오지 않는다. `KafkaTransactionManager` 빈은 `KafkaAutoConfiguration`이 만들어 주지만(`transaction-id-prefix` 설정 시) 트랜잭션 프록시를 켜는 쪽이 클래스패스에 없다.
- 해결(허용): `spring-boot-transaction` 의존성 추가 → `B03.patch`. 같은 근본 원인으로 인정하는 해결: 애플리케이션 클래스에 `@EnableTransactionManagement`를 직접 선언하는 것, `spring-boot-starter-jdbc`/`-data-jpa` 등 이 모듈을 끌고 오는 스타터 추가(단 불필요한 의존성이 늘어남). Boot 4.0.2로 올리는 것은 과제 제약으로 금지.
- 재현 형식: R (`./gradlew test`, 브로커 불필요 — `MockProducer`를 돌려주는 `ProducerFactory` 사용)
- 시그니처: `No transaction is in process`
- 시드 제외: 이 이슈의 원인·해결 기록은 시드에 넣지 않는다.
- 참고: 이슈 원 보고는 "TransactionAutoConfiguration 클래스가 없다"이고, 과제는 그 실제 결과로 나타나는 증상(`@Transactional` 무시)으로 구성했다. 에러 메시지에 `@Transactional`이 언급되지만 이는 spring-kafka의 원래 메시지다.
