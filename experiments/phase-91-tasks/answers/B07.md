## 채점 기준

- 원인(2점): Docker 29가 최소 API 버전을 1.44로 올렸고(스냅샷에서 확인), Testcontainers(docker-java) 클라이언트가 그보다 낮은 API 버전을 써서 거부된다.
- 해결(2점): Testcontainers 2.0.2+ 로 업그레이드 **또는** `api.version=1.44` 명시. (Docker 다운그레이드만 제시하면 1점)
- 감점(-1): Docker 데몬 재시작, 소켓 권한, 네트워크 문제 등 근거 없는 원인을 확정적으로 주장.

## 참고 진단서 (answers/B07.patch가 DIAGNOSIS.md로 추가함)

## 원인

Docker Engine 29.0.0은 데몬이 받는 최소 API 버전을 1.44로 올렸다(환경 스냅샷의 `API version: 1.52 (minimum version 1.44)`). Testcontainers 2.0.1은 환경에 API 버전이 지정되지 않으면 그보다 낮은 고정 API 버전으로 요청하므로 데몬이 모든 전략의 요청을 거부하고, Testcontainers는 "유효한 Docker 환경을 찾지 못했다"고 보고한다.

## 해결

1. Testcontainers를 2.0.2 이상으로 올린다(기본 API 버전이 1.44로 바뀜).
2. 올릴 수 없으면 클라이언트 API 버전을 명시한다: `~/.docker-java.properties` 또는 클래스패스의 `docker-java.properties`에 `api.version=1.44`(또는 `1.52`), 또는 시스템 속성/환경변수 `api.version`.
3. 임시로 Docker Engine을 28.x로 되돌린다.

## 근거

확신: Docker Engine이 29.0.0에서 최소 API 버전을 1.44로 올렸다는 점, 업그레이드 전에는 동작했다는 점. 추정: Testcontainers 2.0.1의 고정 API 버전이 1.44 미만이라는 점(로그에는 거절 사유가 직접 나오지 않음).
