# A10 정답 (에이전트에게 공개하지 않는다)

- 출처: spring-boot#51447 (수정 커밋 53c04499 "Create properties despite used-defined ClientRegistrationRepository", 수정 4.0.9)
- 보고일: 2026-08-25 (이슈 본문은 변경 요청 형태이며 유지보수자가 버그로 판정)
- 증상: 사용자가 `ClientRegistrationRepository` 빈을 직접 정의하면서 `OAuth2ClientProperties`를 주입받으면 컨텍스트가 `NoSuchBeanDefinitionException: No qualifying bean of type '...OAuth2ClientProperties' available`로 뜨지 않는다. 설정(`spring.security.oauth2.client.registration.*`)은 존재한다.
- 근본 원인: `OAuth2ClientConfigurations.ClientRegistrationRepositoryConfiguration`에 클래스 수준 `@ConditionalOnMissingBean(ClientRegistrationRepository.class)`가 붙어 있어, 사용자 정의 저장소가 있으면 같은 구성 클래스의 `@EnableConfigurationProperties(OAuth2ClientProperties.class)`까지 통째로 건너뛴다(조건이 빈 메서드가 아니라 클래스에 걸려 있음).
- 해결(허용): 사용자 구성에 `@EnableConfigurationProperties(OAuth2ClientProperties::class)`를 직접 추가한다 → `A10.patch`. `@ConfigurationPropertiesScan` 등 동등한 방법, `Environment`/`Binder`로 직접 바인딩하는 것도 허용(단 설정 값을 코드에 옮겨 적는 것은 제약 위반). Boot 4.0.9로 올리는 것은 금지.
- 재현 형식: R (`./gradlew test`, 서버 불필요)
- 시그니처: `No qualifying bean of type 'org.springframework.boot.security.oauth2.client.autoconfigure.OAuth2ClientProperties' available`
- 시드 제외: 이 이슈의 원인·해결 기록은 시드에 넣지 않는다.
