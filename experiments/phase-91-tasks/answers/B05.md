# B05 정답 (에이전트에게 공개하지 않는다)

- 출처: spring-boot#48240 (제목 "Document the need for a JdbcDialect bean when using Spring Data JDBC and AOT", 마일스톤 4.0.1, `type: documentation`). 관련 개선 이슈: spring-boot#47781(open) — 아직 구조적으로 해결되지 않아 4.0.8에서도 그대로 재현된다.
- 보고일: 2025-11-22 (Boot 4.0.0 보고, 이 과제는 4.0.8에서 재현 확인)
- 증상: `processAot` 단계에서 `AotProcessingException: Error executing 'BeanRegistrationsAotProcessor': Error creating bean with name 'jdbcDialect' ... Failed to determine a suitable driver class`. 테스트와 `bootRun`(환경 변수로 접속 정보가 주어진 상태)은 정상.
- 근본 원인: Spring Data JDBC가 AOT 처리 중 `JdbcDialect` 빈을 만들려고 `DataSource`/`NamedParameterJdbcTemplate`을 초기화하는데(실제 DB에 접속해 방언을 판별), 빌드 시점에는 접속 정보가 없어 드라이버 클래스를 결정하지 못한다. (설계상 동작이고 이슈는 문서화로 닫힘.)
- 해결(허용): 방언 빈을 직접 정의해 DB 접속 없이 방언을 고정 → `B05.patch`(`JdbcPostgresDialect.INSTANCE`를 반환하는 `JdbcDialect` 빈). 그 외: 빌드 시점에 살아 있는 DB와 접속 정보를 주는 것은 제약 위반. `spring.data.jdbc.dialect` 프로퍼티는 이 문제를 해결하지 못함을 확인했다.
- 재현 형식: R (`./gradlew test processAot`, Docker 불필요. `processAot`는 GraalVM 설치 없이 실행된다 — `org.graalvm.buildtools.native` 플러그인은 AOT 태스크를 등록하기 위해 필요)
- 시그니처: `Failed to determine a suitable driver class`
- 시드 제외: 이 이슈의 원인·해결 기록은 시드에 넣지 않는다.
- 주의: 출처 이슈가 문서화 이슈라 "버그 수정" 유형이 아니라 "설정 누락/문서에 있는 제약" 유형이다. 테스트가 H2의 PostgreSQL 모드를 쓰는 것은 해결 패치(PostgreSQL 방언)와 테스트가 공존하게 하려는 것이다. processAot가 test보다 먼저 실행되면 test 결과가 로그에 안 나올 수 있다.
