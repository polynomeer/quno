# A05 정답 (에이전트에게 공개하지 않는다)

- 출처: spring-data-jpa#4359 (수정 4.1.2 = 2026.0.2)
- 보고일: 2026-09-19 (보고는 Hibernate 7.4 기준이지만, Boot 4.0.8의 Spring Data JPA 2025.1.x에서도 동일하게 재현됨 — 이슈 본문의 `token recognition error at: '%'` 대신 `At 1:38 and token '%', mismatched input '%', ...`로 메시지만 다르다)
- 증상: 리포지토리 빈 생성 시점에 `QueryCreationException` ← `BadJpqlGrammarException: ... mismatched input '%' ... Bad HQL grammar [select c from Call c where c.duration % 2 = 0 order by c.id]` (`@DataJpaTest` 컨텍스트 로드 실패)
- 근본 원인: Spring Data JPA의 `Hql.g4`가 곱셈 계열 연산자로 `*`와 `/`만 허용하고 `%`(나머지)를 정의하지 않는다. Hibernate의 자체 HQL 문법은 `%`를 받아들이지만 Spring Data가 `@Query`를 먼저 자체 파서로 검증하면서 거부한다.
- 해결(허용): `%` 대신 표준 함수 `mod(c.duration, 2) = 0`로 쿼리를 바꾼다 → `A05.patch`. 네이티브 쿼리(`nativeQuery = true`)나 `Specification`/Criteria로 옮기는 것도 결과 계약을 지키면 허용. Spring Boot를 4.1.2로 올리는 것은 과제 제약으로 금지.
- 재현 형식: R (`./gradlew test`, H2 인메모리 + `@DataJpaTest`)
- 시그니처: `mismatched input '%'`
- 시드 제외: 이 이슈의 원인·해결 기록은 시드에 넣지 않는다.
