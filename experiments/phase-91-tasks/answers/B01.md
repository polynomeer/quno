# B01 정답 (에이전트에게 공개하지 않는다)

- 출처: spring-boot#49012 (`status: invalid`로 닫힘 — Boot 버그가 아니라 의존성 누락. 이슈 댓글에서 정답 확인됨)
- 보고일: 2026-01-28 (Boot 4.0.2, Flyway 11.14.1, PostgreSQL 18.1)
- 증상: `BeanCreationException ... Failed to initialize dependency 'flywayInitializer' ...: Unsupported Database: PostgreSQL 18.1` — 컨텍스트가 뜨지 않는다. 접속 자체는 성공한다.
- 근본 원인: Flyway 10+부터 데이터베이스별 지원이 별도 모듈로 분리되어 `flyway-core`만으로는 PostgreSQL을 인식하지 못한다. `spring-boot-starter-flyway`는 `flyway-core`만 가져온다(`flyway-database-postgresql` 없음). 이슈 댓글(bclozel): 전용 모듈 `org.flywaydb:flyway-database-postgresql`을 추가하면 해결, 보고자도 확인.
- 해결(허용): `org.flywaydb:flyway-database-postgresql` 의존성 추가(버전은 Boot BOM이 관리) → `B01.patch`. `runtimeOnly`로 추가해도 동일. PostgreSQL 이미지를 낮추거나 Flyway를 끄는 것은 제약 위반.
- 재현 형식: D (Docker 필요. `CHECK`가 `docker run postgres:18.1`을 직접 띄우고 `trap`으로 지운다. 호스트 포트는 임의 할당)
- 시그니처: `Unsupported Database: PostgreSQL 18.1`
- 시드 제외: 이 이슈의 원인·해결 기록은 시드에 넣지 않는다.
- 주의: "Boot 버그"가 아니라 문서화된 의존성 누락 유형이라, 에이전트가 쉽게 풀 가능성이 높다(난이도 낮음 구간 후보).
