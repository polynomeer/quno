# A09 정답 (에이전트에게 공개하지 않는다)

- 출처: spring-framework#37427 (수정 마일스톤 7.1.0-RC1; 7.0.x로는 백포트되지 않아 Boot 4.0.8의 Framework 7.0.x에서 재현됨)
- 보고일: 2026-10-08
- 증상: `partner-api.connect-timeout=30d`(25일 초과)에서 `RestClient` 빈 생성이 `IllegalArgumentException: Timeout must be a non-negative value`로 실패해 컨텍스트가 뜨지 않는다. `7d`는 정상.
- 근본 원인: `ReactorClientHttpRequestFactory.setConnectTimeout(Duration)`가 `(int) duration.toMillis()`로 좁혀 캐스팅해 `Integer.MAX_VALUE`ms(약 24.8일)를 넘으면 오버플로(30일은 음수)하고, int 버전의 검증("non-negative")에 걸린다. 같은 캐스트 때문에 `SimpleClientHttpRequestFactory`는 음수를 조용히 무시하고, 50일 같은 값은 엉뚱한 양수(약 25초)가 된다.
- 해결(허용): 애플리케이션에서 `Int.MAX_VALUE`ms로 상한을 두어 전달한다 → `A09.patch`. `HttpClient` 계열의 다른 요청 팩토리(`JdkClientHttpRequestFactory` 등 Duration을 그대로 쓰는 것)로 바꾸는 것은 `ReactorClientHttpRequestFactory` 유지 제약 위반. 값을 `0`이나 짧게 바꾸는 것, Framework 버전 상향도 금지.
- 재현 형식: R (`./gradlew test`, 서버 불필요)
- 시그니처: `Timeout must be a non-negative value`
- 시드 제외: 이 이슈의 원인·해결 기록은 시드에 넣지 않는다.
