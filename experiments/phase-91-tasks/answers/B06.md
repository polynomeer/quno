# B06 정답 (에이전트에게 공개하지 않는다)

- 출처: spring-boot#48254 (수정 4.0.1, `type: regression`; 수정 커밋 949c22769 "Restore ApplicationServletEnvironment in web deployments")
- 보고일: 2025-11-23 (Boot 4.0.0, 외부 Tomcat 11 WAR 배포, `context.xml`의 `<Parameter>`가 `spring.datasource.*`에 반영되지 않음)
- 증상: 서블릿 컨텍스트 초기화 파라미터(Tomcat `context.xml` `<Parameter>`)로 준 설정이 `Environment`에 보이지 않는다. 이 과제에서는 `PlaceholderResolutionException: Could not resolve placeholder 'storage.root' in value "${storage.root}"`로 빈 생성 실패.
- 근본 원인: Boot 4 모듈화로 `WarDeploymentApplicationContextFactory`가 `getEnvironmentType()`을 구현하지 않는다. `SpringApplication`이 환경 타입을 `DEFAULT` 팩토리(`ServletWebServerApplicationContextFactory`, `spring-boot-web-server` 모듈)에서 폴백으로 얻는데, WAR에서 내장 Tomcat 스타터를 `provided`로 빼면 이 모듈이 클래스패스에 없어 환경이 `ApplicationEnvironment`(비-서블릿)로 변환된다. 그러면 `servletContextInitParams`가 스텁으로 남아 초기화 파라미터가 채워지지 않는다.
- 재현 방식(편차): 외부 Tomcat 없이 `MockServletContext`(필터/서블릿 등록을 받아 주도록 서브클래스)에 초기화 파라미터를 넣고 `SpringBootServletInitializer.createRootApplicationContext`를 호출한다. 내장 Tomcat 스타터 제외(`exclude starter-tomcat`)가 WAR의 `providedRuntime`을 흉내 낸다. 이 제외가 없으면(= `spring-boot-web-server`가 클래스패스에 있으면) 4.0.0에서도 재현되지 않는다.
- 해결(허용): `ServletInitializer.configure`에서 `builder.environment(StandardServletEnvironment())`로 서블릿 환경을 명시 → `B06.patch`. 같은 근본 원인으로 인정하는 해결: `spring-boot-web-server` 의존성을 클래스패스에 추가(검증함, 단 WAR에 모듈이 들어감). Boot 4.0.1로 올리는 것은 금지. 값을 `application.properties`에 넣거나 기본값을 주는 것은 제약 위반.
- 재현 형식: R (Docker/외부 컨테이너 불필요, `./gradlew test`)
- 시그니처: `Could not resolve placeholder 'storage.root'`
- 시드 제외: 이 이슈의 원인·해결 기록은 시드에 넣지 않는다.
- 주의: 실제 Tomcat에서의 재현은 아니다(모의 서블릿 컨텍스트). 경로의 핵심(환경 타입 폴백)은 컨테이너 독립적이라 동일하게 발현된다.
