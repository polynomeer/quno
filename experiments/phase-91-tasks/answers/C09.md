# C09 정답 (통제군 — 에이전트에게 공개하지 않는다)

- 분류: C층 통제군. 흔하고 문서화된 에러 — 코딩 에이전트가 혼자 풀 수 있어야 하는 과제.
- 증상: 예외는 나는데 롤백되지 않아 데이터가 남는다. `AssertionFailedError: 실패한 묶음은 롤백되어야 한다 ==> expected: <0> but was: <2>` (에러 이름이 없는 "조용한" 실패라는 점이 C층의 다른 과제와 다르다.)
- 근본 원인: `@Transactional`은 프록시를 통해 호출될 때만 적용된다. `importBatch`가 같은 객체의 `saveAll`을 `this`로 호출(자기 호출)해 프록시를 우회하므로 트랜잭션이 시작되지 않고, JDBC autocommit으로 앞 주문이 이미 커밋된다.
- 해결(허용): `@Transactional`을 진입점인 `importBatch`로 옮김 → `C09.patch`. 또는 `saveAll`을 별도 빈으로 분리해 주입받아 호출, `TransactionTemplate` 사용. 검증 시점·예외 동작·`importBatch` 시그니처는 유지.
- 문서: [Spring Framework: AOP 프록시 이해(자기 호출 주의)](https://docs.spring.io/spring-framework/reference/core/aop/proxying.html) (curl -sI -L 200 확인)
- 재현 형식: R (`./gradlew test`)
- 시그니처: `실패한 묶음은 롤백되어야 한다 ==> expected: <0> but was: <2>`
- 시드 제외 여부: 해당 없음(통제군).
