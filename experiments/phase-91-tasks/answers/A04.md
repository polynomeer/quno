# A04 정답 (에이전트에게 공개하지 않는다)

- 출처: spring-framework#37264 (수정 7.0.10, 커밋 1ea92339)
- 보고일: 2026-09-10 (Framework 7.0.9 / Boot 4.1.1에서 보고, Boot 4.0.8의 Framework 7.0.9에서도 동일하게 재현됨)
- 증상: 빈 파일 파트 뒤에 다른 파트가 있으면 컨트롤러의 `@RequestPart FilePart?`가 `null`로 들어온다(`no file received`). 빈 파일이 마지막 파트면 정상. `Response body expected:<received: test.txt> but was:<no file received>`
- 근본 원인: `MultipartParser`의 `BodyState`가 본문이 빈 파트(경계 구분자가 곧바로 나오는 경우)에서 빈 `BodyToken(last=true)`를 방출하지 않는다. `DefaultPartHttpMessageReader`는 `Token::isLast`로 파트를 윈도잉하므로 빈 파일 파트의 윈도가 닫히지 않고 다음 파트의 토큰과 합쳐져 파일 파트가 사라진다. 마지막 파트인 경우는 gh-30953에서 별도로 처리돼 있었다. 청크 분할과 무관하게 결정적으로 재현된다.
- 해결(허용): `@RequestPart` 대신 `@RequestBody Flux<PartEvent>`로 파트를 받아 직접 조립한다 → `A04.patch`. (`PartEventHttpMessageReader`는 `HeadersToken` 기준으로 윈도잉해 빈 본문을 처리한다.) 요청 전처리로 본문을 고치는 식의 우회, 커스텀 `HttpMessageReader` 등 다른 우회도 응답 계약을 지키면 허용. Framework 7.0.10으로 올리는 것은 과제 제약으로 금지.
- 재현 형식: R (`./gradlew test`, 실서버 + `WebTestClient.bindToServer`로 curl과 같은 형태의 원시 multipart 본문 전송)
- 시그니처: `Response body expected:<received: test.txt> but was:<no file received>`
- 시드 제외: 이 이슈의 원인·해결 기록은 시드에 넣지 않는다.
