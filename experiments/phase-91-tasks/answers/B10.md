## 채점 기준

- 원인(2점): Windows에서 자격 증명 헬퍼가 `.cmd`이고 Java `ProcessBuilder`가 확장자 없는 이름을 직접 실행하지 못한다(`cmd /c` 필요). (헬퍼를 못 찾는다는 수준이면 1점)
- 해결(2점): 수정된 Boot로 업그레이드 **또는** 레지스트리 자격 증명을 플러그인에 직접 지정 **또는** 헬퍼를 실행 가능한 형태로 제공/푸시 분리.
- 감점(-1): GCP 권한/토큰 만료/네트워크로 확정.
- 상태: 이슈 spring-boot#48961 (2026-01-24), 수정 PR #48965 (3.5.11)와 일치. 메인테이너 댓글이 `command()` 덮어쓰기 문제를 지적함.

## 원인

Docker CLI는 `credHelpers`에 적힌 `gcloud`를 보고 `docker-credential-gcloud`를 실행하는데, Windows에서 이 헬퍼는 `docker-credential-gcloud.cmd`(배치 파일)로만 존재한다. `.cmd`는 실행 파일이 아니라 `cmd.exe`를 거쳐야 하는데, Java의 `ProcessBuilder`는 확장자 없는 이름 `docker-credential-gcloud`를 직접 실행하려다 `CreateProcess error=2`(파일 없음)로 실패한다. 플러그인에 Windows에서 `cmd /c`를 앞에 붙이려는 코드가 있지만 `command(...)`를 두 번 호출해 앞의 인자를 덮어써서 `cmd /c`가 실제로는 붙지 않는다. 그래서 자격 증명을 못 얻고 인증 없이 푸시를 시도한다.

## 해결

1. 이 결함이 수정된 Spring Boot 버전으로 올린다(수정은 3.5.11 마일스톤에 포함).
2. 우회: 플러그인 설정(`docker.publishRegistry`)에 토큰/사용자·비밀번호를 직접 주거나, 헬퍼를 `.exe`로 제공하는 방법을 쓴다.
3. 푸시를 `bootBuildImage`가 아닌 `docker push`로 분리한다.

## 근거

확신: 예외 메시지(`Cannot run program "docker-credential-gcloud"`)와 헬퍼가 `.cmd`라는 환경 정보. 추정: 우회 방법의 세부 설정(환경에 따라 다름).
