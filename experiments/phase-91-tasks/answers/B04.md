# B04 정답 (에이전트에게 공개하지 않는다)

- 출처: spring-boot#48653 (수정 4.0.2, `type: regression`)
- 보고일: 2025-12-31 (Boot 4.0.1에서 확인됨)
- 증상: `@SpringBootTest(webEnvironment = RANDOM_PORT)`인데도 관리 서버가 고정 포트로 뜨려 해서, 그 포트가 사용 중이면 `PortInUseException: Port 18081 is already in use` / `Web server failed to start. Port 18081 was already in use.`로 컨텍스트가 뜨지 않는다.
- 근본 원인: Boot 4에서 `SpringBootTestRandomPortEnvironmentPostProcessor`가 `SpringBootTestRandomPortApplicationListener`로 바뀌었는데, 이벤트가 `ContextCustomizerFactory`가 리스너를 등록하기 전에 발행되어 `RANDOM_PORT`가 관리 서버(`management.server.port`)에 적용되지 않는다. 서버 포트만 랜덤이 된다.
- 해결(허용): 테스트 환경에서 `management.server.port=0`을 지정 → `B04.patch`(테스트 리소스 `config/application.properties`; 테스트 코드는 수정 불가이므로 프로퍼티로). `@SpringBootTest(properties=...)`는 테스트 코드 수정이라 제약 위반. 관리 서버를 `-1`로 끄는 것은 헬스 엔드포인트 제공 제약 위반(테스트가 `local.management.port`를 쓰므로 실패하기도 함). Boot 4.0.2로 올리는 것은 금지.
- 재현 형식: R. 포트를 점유하는 것은 `CHECK`가 직접 한다(IPv6 듀얼스택 소켓으로 18081을 잡고 `trap`으로 해제). 점유하지 않으면 재현되지 않는다.
- 시그니처: `Port 18081 is already in use`
- 시드 제외: 이 이슈의 원인·해결 기록은 시드에 넣지 않는다.
- 주의: 이 과제의 CHECK는 python3가 필요하다. 에이전트가 CHECK를 수정하지 못하게 TASK.md에 명시했다.
