# B02 정답 (에이전트에게 공개하지 않는다)

- 출처: spring-boot#49311 (수정 4.0.4, `type: regression`, `for: upgrade-attention`)
- 보고일: 2026-02-24 (3.5.11 → 4.0.3 업그레이드에서 확인됨)
- 증상: 파트가 11개 이상인 `multipart/form-data` 요청이 컨트롤러에 닿기 전에 `413`으로 거절된다. 서버 로그에 `MaxUploadSizeExceededException: Maximum upload size exceeded`. 테스트 출력: `expected: 200 but was: 413`.
- 근본 원인: `server.tomcat.max-part-count`의 4.0.x 기본값이 10이다(Tomcat 10.1.42 시점의 값). Tomcat 자체 기본값과 3.5.x는 50으로 올라갔지만 4.0.x는 맞춰지지 않았다.
- 해결(허용): `server.tomcat.max-part-count`를 폼 항목 수 이상으로 설정(예: 50) → `B02.patch`. Boot 4.0.4로 올리는 것은 과제 제약으로 금지. 폼을 줄이거나 테스트를 바꾸는 것은 제약 위반.
- 재현 형식: R (`./gradlew test`, 내장 Tomcat RANDOM_PORT + `RestClient`; MockMvc는 Tomcat 제한을 타지 않으므로 쓰지 않았다)
- 시그니처: `but was: 413`
- 시드 제외: 이 이슈의 원인·해결 기록은 시드에 넣지 않는다.
