# Phase 91 과제 프로젝트

[과제 후보 목록](../../docs/product/phase-91-task-candidates.md)의 과제(전체 목록은 [MANIFEST.md](MANIFEST.md))를 실제로 재현 가능한 최소 프로젝트로 만든 것이다. 실험 설계는 [phase-91-validation-experiment.md](../../docs/product/phase-91-validation-experiment.md).

## 구조

| 경로 | 내용 | 에이전트에게 |
|---|---|---|
| `tasks/<ID>/` | 수정 전 버전으로 고정한 Kotlin + Gradle 프로젝트, `TASK.md`(프롬프트), `CHECK`(성공이면 종료 코드 0) | 공개 |
| `answers/<ID>.md` | 출처, 증상, 근본 원인, 허용되는 해결 | **비공개** |
| `answers/<ID>.patch` | 알려진 정답 패치 | **비공개** |
| `answers/<ID>.signature` | 증상 재현을 확인할 출력 문자열 | **비공개** |
| `_common/wrapper/` | 모든 과제가 공유하는 Gradle 래퍼 | 공개(복사됨) |

## 형식: R/D와 L

- **R/D (재현형)**: 프로젝트를 고치고 `./CHECK`가 통과하면 성공. 기계적으로 판정된다.
- **L (로그 재생형, B07~B10)**: 호스트 환경 때문에 저장소로 재현할 수 없는 문제. `tasks/<ID>/evidence/`의 환경 스냅샷과 로그만 주고, 에이전트가 `DIAGNOSIS.md`(`## 원인`/`## 해결`/`## 근거`)를 쓴다. `CHECK`는 형식만 확인하고, **내용은 `answers/<ID>.md`의 채점 기준(0~4점, 감점 -1)으로 조건을 가린 평가자가 채점한다.** 결과는 R/D와 **따로 집계**한다(엄밀성이 다르다). 증거는 이슈 본문의 사실만 옮기고 지어낸 줄을 넣지 않는다.

## 스크립트

```bash
scripts/prepare.sh A01          # 에이전트용 작업 디렉터리를 만들어 경로를 출력 (answers 미포함)
scripts/verify-repro.sh A01     # 수정 전 버전에서 증상이 실제로 재현되는지 확인
scripts/verify-solution.sh A01  # 정답 패치를 적용하면 CHECK가 통과하는지 확인
```

**두 검증을 모두 통과해야 과제로 확정할 수 있다.** 재현이 안 되면 "문제가 없는 과제"가, 정답이 안 통하면 "풀 수 없는 과제"가 되어 실험이 오염된다.

## 규약

- 에이전트는 `prepare.sh`가 만든 임시 디렉터리에서만 작업한다. 저장소 전체(정답·이슈 링크 포함)를 보여 주지 않는다.
- **버전 고정**: 모든 과제의 `TASK.md`는 문제가 되는 의존성 버전을 올리지 말라는 제약을 명시한다(수정 버전으로 올리면 풀리는 과제가 많기 때문. 후보 목록 6절 참고).
- `TASK.md`는 증상과 성공 기준만 말하고, 원인이나 이슈 번호는 말하지 않는다.
- `CHECK`는 앱/테스트의 종료 코드만 믿지 않는다 — 과제마다 실제로 성공한 것이 맞는지 출력·결과로 판정한다.
- 첫 실행은 의존성을 내려받느라 느리다. 네트워크가 필요하다.

## 실행 요건

- JDK 21, 네트워크(Maven Central), `bash`.
- B01은 Docker(`postgres:18.1` 이미지), B04·C05는 `python3`가 필요하다(CHECK가 포트를 점유한다).
- C05는 8080 포트를 쓴다. 이미 다른 프로세스(예: Docker Desktop)가 8080을 점유한 호스트에서도 같은 에러가 나지만, 포트가 비어 있어야 점유 단계가 정상 동작한다.
- 과제를 **병렬로** 검증하면 Gradle 데몬이 사라지는 등 간헐적으로 실패했다. 검증은 순차로 돌린다.
- 26개 전체 순차 검증(repro + solution)은 수십 분이 걸린다.
