# ADR-0085: 조직 범위 비공개 질문 — 인증 조직만, 숨긴 질문은 "없는 질문"과 같은 404, URL 게이트 + 필수 viewer 하이드레이터 + SQL 필터의 3중 방어

- 날짜: 2026-11-02
- 상태: 승인됨

## 배경 (Context)

지금까지 모든 질문은 공개였다. PLAN.md Phase 79는 조직 안에서만 보이는 질문을 요구한다. 사내 정보가 담긴 질문을 올릴 곳이 생겨야 하고, IDE 연동(88)의 선행 조건이기도 하다.

어려운 점은 기능이 아니라 **누수**다. 질문은 수십 개 경로로 밖에 드러난다. 조사로 찾은 경로는 약 70개다(PR 설명에 목록을 남겼다).

- 상세·판본·diff
- 답변·댓글
- 검색·관련 질문·태그 목록
- 대시보드·Flow·추천
- 프로필
- 알림
- 라이브챗(STOMP)
- Direct Ask
- 에러 시그니처
- 버전 영향
- Fork·클러스터
- 서버 메타데이터(OG)

경로마다 검사를 하나씩 붙이면 언젠가 하나를 빠뜨린다. 새 엔드포인트를 만드는 사람이 기억해야만 지켜지는 규칙은 지켜지지 않는다.

## 결정 (Decision)

### 모델

- `questions.visibility`(`PUBLIC`|`ORG`)와 `organization_id`를 둔다(V34). `organization_id`는 ORG일 때만 있다(DB CHECK와 도메인 `init`이 둘 다 강제).
- **범위는 작성할 때 정하고 바꾸지 않는다.** ORG를 PUBLIC으로 바꾸는 것은 79.3 "정제 후 공개"의 몫이다. 사내 정보를 지운 새 공개 카드로 승격해야 한다. 그냥 공개로 돌리면 과거 판본에 남은 사내 정보까지 공개된다.
- **ORG 질문은 인증 조직에만 허용한다**(사용자 확인).
  - 커뮤니티 조직은 누구나 버튼 하나로 가입한다. 그런 곳의 "멤버만"은 아무것도 지켜주지 않는다.
  - 인증 조직의 멤버십은 회사 이메일 인증으로만 생긴다(ADR-0035).
- **볼 수 있는 사람:**
  - PUBLIC이면 누구나.
  - ORG면 그 조직 멤버, 그리고 작성자(조직을 떠나도 자기 질문은 본다).

### 숨긴 질문은 "없는 질문"과 똑같이 보인다

볼 수 없는 질문에는 403이 아니라 **404**를 돌려준다. 메시지도 존재하지 않는 질문과 같다. 403은 "여기 무언가 있다"고 알려주는 셈이고, id를 하나씩 넣어 보며 비공개 질문의 존재를 탐지하는 데 쓰인다.

답변·댓글·라이브챗 방처럼 질문에 딸린 자원도 각자의 "not found"를 그대로 쓴다.

### 3중 방어

1. **URL 게이트**(`QuestionVisibilityGate`, HandlerInterceptor)
   - 대상: 아래 패턴의 모든 요청이다. 읽기와 쓰기 모두 포함한다.
     - `/api/v1/questions/{id}/**`
     - `/answers/{id}/**`
     - `/comments/{id}/**`
     - `/live-chat/{id}/**`
     - `/direct-asks/{id}/**`
     - `/engine-suggestions/{id}/**`
   - 이 요청들은 자원을 질문으로 되짚어 검사한 뒤에야 컨트롤러에 닿는다.
   - 컨트롤러가 아니라 URL로 매칭하므로, 이 경로 아래 새로 만든 엔드포인트도 자동으로 보호된다.
   - STOMP는 `StompQuestionVisibilityInterceptor`가 같은 규칙으로 SUBSCRIBE·SEND를 검사한다. 알 수 없는 `/topic`은 거절한다(지금 모든 topic이 질문에 속하므로, 새 topic은 일부러 등록해야 열린다).
2. **필수 viewer 하이드레이터**
   - `QuestionSummaryHydrator.hydrate(ids, viewer)`의 `viewer`에 기본값이 없다. 그래서 순위를 매긴 id를 화면용 요약으로 바꾸는 모든 경로가 "누가 보는가"를 컴파일러 수준에서 정해야 한다.
   - 순위 쿼리가 무엇을 반환했든 여기서 볼 수 없는 질문은 버린다. 마지막 방어선이다.
3. **SQL 필터**
   - LIMIT으로 자르는 순위 쿼리는 쿼리 안에서 거른다: 검색 2종, 관련 질문, 태그별 3종, 추천, 에러 시그니처 매칭, 버전 영향. 하이드레이터에서만 거르면 페이지가 비어 버린다.
   - 조건은 `visibility = 'PUBLIC' OR author_id = :viewer OR organization_id IN (:orgs)`이다.
   - 빈 조직 목록은 `-1` 센티널로 채워 쿼리 모양을 고정한다.

### 경로별 규칙

- **공동체 집계는 PUBLIC만 센다.** 대상: 인기 질문, 오늘 해결, 재활성 지식, 트렌드 태그, 태그 스파이크, Flow 카드, 태그 기여자, 연관 태그. 인기·트렌드·스파이크는 viewer 구분 없이 Redis 캐시를 공유한다. 캐시 키에 조직을 넣는 것보다 비공개를 아예 세지 않는 편이 단순하고 안전하다.
- **개인 목록은 읽을 때마다 다시 검사한다.** 대상: 프로필(질문·답변), 저장, Watch, 알림, Direct Ask, 스택 Ward 제안. 조직을 떠난 사람에게서 즉시 사라진다.
  - 이 use case들의 viewer 기본값은 "조직 없음"이다. 기본값은 더 숨길 뿐, 더 보여주지 않는다.
- **알림은 발송 시점에 멤버십을 확인한다.** Watch·@멘션·작성자 알림 모두, ORG 질문이면 멤버나 작성자가 아닌 수신자를 뺀다. 이벤트를 쓸 때가 아니라 보낼 때 확인하므로, 조직을 떠나면 그 즉시 끊긴다.
- **본문으로 들어오는 id는 use case가 직접 검사한다.** URL 게이트는 요청 본문을 보지 않기 때문이다.
  - "같은 문제" 클러스터: `relatedQuestionId`
  - 슈퍼 답변 지정: `answerId`
- **Fork는 원본 범위를 잇는다.** 내용을 복사하므로 Fork로 비공개가 공개가 되면 안 된다.
- **클러스터는 범위가 같은 질문끼리만 묶는다**(모두 PUBLIC, 또는 모두 같은 조직). 슈퍼 답변은 클러스터 전체에 보이므로, 섞이면 비공개 답변이 공개 질문에 노출된다.
- **Direct Ask는 그 조직 멤버에게만 보낼 수 있다.**
- **서버 메타데이터(OG)는 익명으로 조회한다.** 비공개 질문은 404로 보이므로 중립 제목과 noindex를 쓰고, 멤버에게는 클라이언트가 실제 제목을 설정한다.
- **외부 전송은 지금 없다.** 엔진(ADR-0081)은 프로세스 안에서만 돈다. AI 응답자(ADR-0068)와 러너(Phase 80)가 생길 때 지킬 원칙은 하나다: ORG 질문 내용은 기본적으로 외부 모델·러너로 보내지 않고, 조직 정책으로만 연다.

### 의도적으로 남긴 것

- **태그 이름:** 태그는 전역 어휘다. 비공개 질문이 새로 만든 태그 이름은 태그 목록과 sitemap에 보인다. 태그 통계와 태그별 질문 목록에서는 비공개 질문을 뺀다. 사내 코드명은 태그로 쓰지 말라고 안내하는 것으로 대신한다. 태그 생성을 막으면 비공개 질문만 분류할 수 없게 된다.
- **평판·배지 수:** 비공개 질문과 답변도 평판과 배지에 센다. 공개 프로필의 "질문 3"이 목록의 두 개보다 많을 수 있다. 내용도 질문 주소도 드러나지 않는 숫자뿐이다. 사내에서 한 기여를 지우면 비공개 질문을 쓸 이유가 줄어든다.
- **전역 운영 지표**(`/metrics`): 전체 건수뿐이고 인증 사용자 전용이다.
- **모더레이터:** 신고 대상의 id와 신고 사유만 보며 내용은 받지 않는다. 조직별 모더레이션은 조직 정책과 함께 다룬다.

## 결과 (Consequences)

- 누수 E2E가 비공개 질문 하나로 다음을 확인한다.
  - 상세·판본·답변·댓글·라이브챗·Fork·투표 등 질문별 경로: 외부인과 비로그인에게 404
  - 검색·태그 목록·프로필·Flow·대시보드·추천·버전 영향·에러 시그니처·알림: 토큰이 나타나지 않음
  - 멤버: 모두 정상으로 보임
- 새 엔드포인트가 위 URL 패턴 아래 있으면 자동으로 보호된다. 그 밖에서 질문을 내보내는 새 목록은 하이드레이터가 viewer를 요구하므로, 무엇을 넘길지 컴파일 단계에서 정해야 한다.
- 요청마다 조직 목록을 한 번 읽는다(`organization_memberships`의 user 색인). 게이트도 대상 자원을 하나 더 읽는다. 질문 단위 경로에만 걸리므로 비용이 작다.
- 79.3(정제 후 공개 카드 승격)과 조직 정책(외부 모델 전송 허용 등)은 다음 단계다.
