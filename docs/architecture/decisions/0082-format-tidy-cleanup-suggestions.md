# ADR-0082: 정리 제안(format-tidy) — 세 가지만, 확신이 없으면 제안하지 않고, 무시한 종류는 그 질문에서 다시 꺼내지 않는다

- 날짜: 2026-11-01
- 상태: 승인됨

## 배경 (Context)

[ADR-0081](0081-engine-suggestion-layer-and-secret-masking.md)로 엔진 제안 레이어와 첫 엔진(비밀정보)이 생겼다. PLAN.md 78.5는 그 위에 정리 제안을 얹는다. 마크다운, 코드 펜스 언어, 긴 로그 접기를 PR처럼 제안하고, 자동으로 적용하지는 않는다.

정리 제안은 비밀정보와 성격이 다르다. 틀려도 해가 작지만, 너무 자주 나오면 잔소리가 된다. 그래서 정할 것은 셋이다.

- 무엇을 제안할지
- 확신을 어느 정도로 요구할지
- 거절을 어떻게 기억할지

## 결정 (Decision)

### 엔진과 제안 종류

`format-tidy` 엔진(버전 1)은 질문 본문에서 세 가지만 제안한다.

| 종류 | 조건 | 제안 |
|---|---|---|
| `FENCE_STACK_TRACE` | 코드 블록 밖에 `at ...(...)` 스택 프레임이 3줄 이상 연속 | 바로 위의 예외 줄까지 포함해 ` ```text ` 블록으로 감싼다 |
| `ADD_CODE_FENCE_LANGUAGE` | 언어 표기가 없는 코드 블록인데 내용이 한 언어로 분명히 읽힘 | 언어를 붙인다(json·xml·sql·kotlin·java·yaml·bash·text) |
| `MOVE_LONG_LOG` | 로그 칸이 비어 있고, 본문에 30줄 이상이면서 절반 이상이 타임스탬프·스택 프레임인 코드 블록이 있음 | 그 블록을 로그 칸으로 옮긴다(화면에서 접혀 보인다) |

- **"마크다운 정리" 일반은 하지 않는다.** 줄바꿈·제목 수준·목록 같은 서식은 사람마다 취향이 다르다. 규칙으로 고치면 제안이 맞아도 잔소리처럼 느껴진다. 위 셋은 읽기 어려움이 분명한 경우만 고른 것이다.
- **확신이 없으면 제안하지 않는다.** 언어 판별은 여러 신호가 함께 맞을 때만 이름을 붙인다. 예를 들어 Kotlin은 `fun`·`val` 같은 선언이 있고 Java 클래스 표지가 없어야 한다. 틀린 언어 표기는 표기가 없는 것보다 나쁘다.
- 로그를 옮기면 본문이 비는 경우에는 제안하지 않는다. 질문 본문은 비어 있을 수 없다.

### 제안끼리의 관계

- 제안 하나는 하나의 고칠 거리다. 각 제안은 같은 판본 본문에서 출발한다.
- 하나를 수락하면 새 판본이 생겨 나머지는 `SUPERSEDED`가 된다. 엔진이 새 판본을 다시 분석해 아직 해당하는 것만 다시 제안한다.
- 그래서 제안을 합치거나 순서를 정하는 로직이 필요 없다.

### 거절의 기억

- **작성자가 어떤 정리 종류를 무시하면, 그 질문에서는 그 종류를 다시 제안하지 않는다.** 무시는 놓친 것이 아니라 그 질문에 대한 선호로 본다.
- 판본이 바뀔 때마다 같은 제안이 되살아나면 엔진이 사람을 이기려 드는 꼴이 된다(ADR-0068 "엔진은 제안만 한다").
- 비밀값의 무시는 값 단위 허용 목록(ADR-0081)으로 기억하고, 정리 제안의 무시는 종류 단위로 기억한다. 비밀값은 값마다 판단이 다르고, 서식은 질문마다 판단이 같기 때문이다.

### 실행과 알림

- 엔진마다 실행 기록(`engine_runs`)을 따로 둔다. 한 엔진의 버전만 올려도 그 엔진만 전체를 다시 분석한다. 스윕은 모든 엔진의 미분석 질문을 함께 모아 처리한다.
- 정리 제안은 알림을 보내지 않는다. 작성자가 자기 질문에서 마주치면 충분하고, 기존 질문 백필로 알림이 쏟아지는 것을 막는다.
- 화면의 "바뀔 내용"은 현재 내용과의 줄 단위 diff로 보여준다. 펜스 두 줄을 더하는 제안을 본문 전체로 보여주면 무엇이 바뀌는지 찾기 어렵다.

## 결과 (Consequences)

- 기존 질문에도 스윕을 통해 정리 제안이 쌓인다. 작성자가 질문을 다시 열기 전까지는 보이지 않으므로 부담이 없다.
- 판별 규칙이 보수적이라 놓치는 경우(미탐)가 많다. 오탐을 줄이는 쪽을 택했다. 규칙을 넓히면 엔진 버전을 올려 다시 분석한다.
- 답변·댓글의 서식은 다루지 않는다. 답변 리비전 경로가 생기면 같은 분석기를 붙인다.
