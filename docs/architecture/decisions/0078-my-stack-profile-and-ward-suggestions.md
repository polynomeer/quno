# ADR-0078: 내 스택 — 사용자 스택 프로필을 질문 지문과 같은 모델로 저장하고, 패키지가 겹치는 질문을 Ward 후보로 제안만 한다

- 날짜: 2026-10-27
- 상태: 승인됨

## 배경 (Context)

[ADR-0076](0076-stack-fingerprint-dependency-parsing.md)으로 질문에, [ADR-0077](0077-answer-applicability-range-and-narrowed-impact.md)로 답변에 패키지 정보가 붙었다. PLAN.md Phase 63.5는 마지막 조각인 "내 스택"이다. 사용자가 자기 프로젝트의 의존성을 저장해 두면, 같은 패키지를 쓰는 질문을 Ward(구독)할 후보로 제안한다. 단, 구독은 옵트인이어야 한다.

이 결정에서 정할 것은 두 가지다.

- **"자동 구독"을 어디까지 자동으로 할지.** 저장 즉시 겹치는 질문을 모두 구독하는 방식과, 새 질문이 올라올 때마다 계속 자동 구독하는 방식도 가능하다.
- **무엇을 "겹친다"고 볼지.** 패키지만 같으면 되는지, 버전까지 같아야 하는지.

## 결정 (Decision)

### 저장

- `user_stack_dependencies`에 질문 지문과 같은 `(생태계, 패키지, 버전)` 항목을 둔다.
  - 사용자당 하나의 목록이다.
  - 상한은 질문과 같은 200개다.
  - 원본 파일은 저장하지 않는다.
  - 사용자를 지우면 함께 지운다(CASCADE).
- 입력은 질문 작성과 같은 흐름이다. 붙여넣기 → `POST /stack-fingerprints/parse` 미리보기 → 남길 항목 선택.
- 저장은 `PUT /me/stack`으로 목록을 통째로 교체한다. `[]`를 보내면 비운다.
- 내 스택은 **본인만 본다.** 공개 프로필에 노출하지 않는다. 사내 패키지 구성은 질문보다 더 민감할 수 있다.

### 제안은 하되 구독은 사용자가 한다

- `GET /me/stack/ward-suggestions`는 내 스택과 패키지(생태계 + 이름)가 하나라도 겹치는 질문을 돌려준다.
  - 제외: 삭제된 질문, 내 질문, 이미 구독 중인 질문
  - 순서: 겹치는 패키지 수가 많은 순, 그다음 최신순
  - 각 질문에는 겹친 패키지 목록이 붙는다.
- 구독은 화면에서 사용자가 고른 질문만 기존 `POST /questions/{id}/watch`로 한다. "모두 구독" 버튼도 결국 사용자의 클릭이다.
- **새 질문의 자동 구독은 하지 않는다(기각).** 저장해 둔 스택 하나로 앞으로 올라올 질문을 계속 구독하면, 알림 수를 사용자가 통제하지 못한다. Ward 알림은 질문의 모든 활동(답변, 수정, 댓글)으로 퍼지므로 늘어나는 폭이 크다. 필요해지면 그때 별도 설정으로 다룬다.

### 겹침 판정은 패키지 단위

- 버전은 판정에 쓰지 않는다. 같은 패키지의 다른 버전에서 생긴 질문도 업그레이드를 앞둔 사용자에게는 쓸모가 있다.
- 버전은 화면에 함께 보여 사용자가 판단하게 한다.

## 결과 (Consequences)

- Phase 63(Stack Fingerprint)이 끝난다. 질문·답변·사용자가 같은 의존성 모델을 공유한다.
- 제안의 질은 지문이 붙은 질문 수에 달려 있다. 지금은 대부분의 질문에 지문이 없어 제안이 적다. CLI(Phase 65)와 환경 스냅샷(Phase 93)이 지문을 늘리는 경로다.
- 범용 패키지(`kotlin-stdlib`, `react`)는 거의 모든 질문과 겹친다. 그래서 제안 순서를 "겹친 수"로 매겨 구체적인 조합이 위로 오게 했다. 이것으로 부족하면 패키지별 희소도 가중치를 검토한다.
