# ADR-0002: 기각된 대안 기획(StackNext, MySQL+Kafka)은 삭제 대신 참고 아카이브로 보관

- 날짜: 2026-08-24
- 상태: 승인됨

## 배경 (Context)

ADR-0001에서 스택을 확정하면서 StackNext 스타일 기획안과 MySQL+Kafka 백엔드안은 채택되지 않았다. 이 문서들을 그냥 지울지, 어떤 형태로든 남길지 결정해야 했다 — 둘 다 브레인스토밍 단계에서 상당한 분량으로 작성된 원본 자료였다.

## 결정 (Decision)

`docs/archive/`에 원본 `.docx` 등 브레인스토밍 자료를 그대로 보관한다. `docs/archive/README.md`에 "현재 방향과 다른 대안 탐색안(StackNext, MySQL+Kafka 백엔드안)도 여기 보관되어 있으며 활성 기준 문서가 아니다"라고 명시해, 이후 세션이 아카이브 내용을 현재 아키텍처로 착각하지 않도록 한다.

## 결과 (Consequences)

- 대안안에 있었던 아이디어(예: 특정 이벤트 모델링, 특정 상태 전이 아이디어)를 나중에 다시 검토하고 싶을 때 원본을 잃지 않는다.
- `docs/archive/`는 "활성 기준 문서가 아니다"라는 라벨이 붙으므로, 새 세션이 문서를 읽을 때 `CLAUDE.md`의 문서 구조 안내(PLAN.md → product → architecture 순서)를 따르는 한 아카이브를 현재 결정으로 오인할 위험은 낮다.
- 아카이브 자체는 갱신하지 않는다 — 새로운 대안 검토가 필요하면 새 ADR로 남기고, 아카이브는 "당시 왜 이 방향을 택하지 않았는지"의 역사적 기록으로만 둔다.
