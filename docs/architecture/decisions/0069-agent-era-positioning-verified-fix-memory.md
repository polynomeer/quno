# ADR-0069: AI 에이전트 시대의 포지셔닝 — 증거가 붙은 해결 기록소와 AI→사람 에스컬레이션 통로

- 날짜: 2026-10-19
- 상태: 조건부 승인 (가설. Phase 91의 실험 결과로 재검토한다)

## 배경 (Context)

[competitive-analysis.md](../../product/competitive-analysis.md)와 지난 ADR들은 사람이 사이트에 와서 질문을 쓰고 읽는 Q&A 플랫폼을 전제로 기능을 쌓았다([ADR-0067](0067-differentiation-roadmap-priorities-and-boundaries.md), [ADR-0068](0068-living-engine-runner-and-ai-first-responder.md)). 그런데 AI 에이전트가 IDE 안에서 코드를 쓰고 에러를 고치는 시대에 "굳이 Q&A 플랫폼을 쓸 이유가 있는가"라는 근본 질문이 남았다. 사고실험의 결론은 다음과 같다.

- 에러 수정 같은 대부분의 수요는 에이전트가 직접 해결하므로, 사람이 질문 글을 쓰는 사용 방식은 대부분 사라진다.
- 에이전트가 구조적으로 주지 못하는 수요가 남는다: **최신성**(릴리스 직후 무엇이 깨졌나), **검증**(그럴듯하게 틀린 제안을 확인할 증거), **막힌 롱테일**(에이전트가 못 푼 문제를 넘길 통로), **경험 기반 판단**(규모·운영 맥락이 붙은 경험), **팀의 기억**(팀원마다 에이전트가 같은 문제를 처음부터 푸는 낭비), **메인테이너 트리아지**.
- 이 수요의 주 소비자는 사람이 아니라 사용자의 AI 에이전트다.

## 결정 (Decision)

1. **포지셔닝을 바꾼다.** Quno는 "Q&A 사이트"가 아니라 **"AI 에이전트와 개발자가 함께 쓰는, 증거가 붙은 해결 기록소 + 에이전트가 막혔을 때 사람에게 넘기는 통로"**다. 주 소비자는 에이전트(MCP/API), 사람은 기여·판단·에스컬레이션을 맡는다.
2. **주 콘텐츠 단위는 질문 글이 아니라 해결 기록(Resolved Record)과 깨짐 보고다.** 질문 글(에스컬레이션)은 예외 경로다. 해결 기록은 에이전트 세션에서 **동의를 받아** 자동 제출되고 러너가 검증한 뒤에 공개된다. 글을 쓰는 사람이 없어도 공급되므로 콜드 스타트 문제가 달라진다.
3. **신뢰와 공급망 보안은 전제 조건이다.** 에이전트가 신뢰하는 공유 지식은 프롬프트 인젝션·악성 "해결" 주입의 공격면이다. 에이전트에게 주는 필드는 구조화된 데이터만이고, 자유 텍스트는 비신뢰로 분리·표시한다. 모든 기록에 출처·검증 등급·실행 증거를 붙인다(Phase 96).
4. **질문 자체를 증거 자료로 만든다.** 환경 스냅샷 자동 수집과 검증된 질문 등급으로 질문이 "AI가 인용할 수 있는 근거"가 된다 — 세부 원칙은 [ADR-0070](0070-question-as-evidence-environment-snapshot-and-verification-tiers.md).
5. **우선순위를 재정렬한다.**
   - **가설 검증 실험(Phase 91)을 첫 단계로 한다.** 읽기 전용 MCP와 시드 기록으로 에이전트의 조회 히트율과 시간 절감을 먼저 잰다. 91의 결과를 보기 전에는 자동 제출·에스컬레이션(92·95)의 대규모 구현을 시작하지 않는다.
   - **승격**: 63, 64, 65(쓰기 도구 포함), 78, 79, 80~82.
   - **재정의**: 72(사람의 버튼에 더해 에이전트의 자동 보고가 1순위), 88~90(에이전트 연동이 1순위, IDE UI는 보조 채널), 69(깨짐 레이더).
   - **보류·재평가**: 74, 75, 76, 77(사람이 읽고 쓰는 UX 중심), 87(사용자의 에이전트가 이미 1차 응답을 하므로 Quno 쪽 AI 응답은 91에서 수요가 확인되면 착수).
   - 71(질문방 → 답변 게시)은 선행이 없는 독립 작업이고 에스컬레이션의 사람-사람 협업 경로로도 쓰이므로 유지한다.
6. **수익 모델 후보**: 개인은 무료, 팀의 비공개 해결 기억(Phase 97), 벤더·메인테이너용 실패 인텔리전스(Phase 98), 고빈도 API. **기여자 데이터를 AI 학습용으로 외부에 라이선스하지 않는다.** 하게 되려면 기여자 동의 모델을 갖춘 별도 ADR이 필요하다.
7. **특정 에이전트에 종속되지 않는다.** MCP와 공개 API로 열고, 특정 벤더 전용 통합을 기본으로 삼지 않는다.

[ADR-0068](0068-living-engine-runner-and-ai-first-responder.md)의 결정(엔진은 제안만, 격리 러너, AI는 라벨 붙은 비-`Answer`, 비공개 질문 선행)은 모두 유효하다.

## 기각한 대안

- **기존 방향 유지(사람이 쓰는 Q&A 사이트 중심).** AI가 대부분의 수요를 흡수하면 기여자와 독자가 함께 줄어 해자인 그래프 밀도를 만들 수 없다.
- **에이전트 벤더 한 곳과의 전용 통합.** 중립성이 사라지고, 그 벤더가 같은 기능을 직접 만들면 의미가 없어진다.

## 결과 (Consequences)

- **이 결정은 가설이다.** AI가 롱테일까지 풀면 에스컬레이션 수요도 줄고, 남는 가장 방어 가능한 가치는 최신성·검증·팀 기억이다. 그래서 Phase 91에서 먼저 확인한다. 임계치는 91.1에서 정하며, 미달하면 포지셔닝을 재검토한다(예: 팀 비공개 기억 중심으로 축소하거나 사람 중심 Q&A를 다시 강화).
- **에이전트 벤더가 직접 만들 위험**이 있다(자기 세션 데이터를 가진다). 방어선은 중립성, 메인테이너와의 제휴, 검증 가능한 공개 증거인데 확실한 해자는 아니다.
- **커버리지가 얕으면 에이전트가 조회를 포기한다.** 좁은 스택(Kotlin/Spring)에서 밀도부터 만든다.
- 자동 제출은 코드 유출 경로가 될 수 있으므로 동의·로컬 정제·비공개 기본값이 필수다(ADR-0070).
- 이미 계획된 Phase 74~77, 87은 삭제하지 않고 보류로 남겨 91의 결과에 따라 되살릴 수 있게 한다.
