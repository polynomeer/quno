# ADR-0087: 재현 러너 v0 — 사용자 저장소의 GitHub Actions가 실행하고, Quno는 GitHub OIDC 토큰과 재사용 워크플로로 결과를 믿는다

- 날짜: 2026-11-02
- 상태: 승인됨

## 배경 (Context)

PLAN.md Phase 80은 재현 러너의 1단계를 요구한다. Quno가 코드를 직접 실행하지 않고, 외부 CI가 실행한 결과를 받아 다음과 같이 보여 주는 것이다.

> `재현됨 · 환경 · N시간 전 (실행 로그 보기)`

ADR-0068은 코드 실행을 "외부 CI → 호스티드 샌드박스 → 자체 호스팅" 순서로 들이기로 정했다.

PLAN은 Phase 80의 선행으로 66.1(재현 정보 첨부)과 68(GitHub 연동)을 적었다. 둘 다 아직 착수하지 않았다. Phase 80에서 정말 필요한 것은 두 가지다.

- **무엇을 실행하는가:** 66.1의 일부
- **외부 CI가 보낸 결과를 왜 믿는가:** 68의 GitHub App을 전제로 했던 부분

## 결정 (Decision)

### 1. 재현 캡슐: 66.1의 최소 부분을 여기서 만든다

- 질문 작성자가 질문에 **재현 캡슐**을 하나 붙인다.
  - 공개 GitHub 저장소(`owner/name`)
  - ref(브랜치·태그·커밋)
  - 실행 방식(SCRIPT·GRADLE·DOCKERFILE)
  - 명령
- 캡슐을 바꾸면 이전 캡슐은 **대체**된다. 이전 명세로 실행한 결과는 새 캡슐에 이어지지 않는다(V36, 질문당 활성 캡슐은 하나).
- ref가 커밋 sha 40자이면 **그 커밋의 실행만** 인정한다.
- devcontainer 같은 다른 형식은 66.1에 남긴다. "다른 사용자가 자기 환경에서 재현됨/안 됨을 표시"하는 기능(사람의 보고)도 66.1에 남긴다.

### 2. 실행: 사용자 저장소의 GitHub Actions, Quno의 재사용 워크플로

- Quno는 아무것도 실행하지 않는다. 캡슐 저장소의 소유자가 `polynomeer/quno/.github/workflows/reproduce.yml`을 `uses:`로 호출하는 워크플로 하나를 추가한다. 질문 화면에서 그 설정을 복사할 수 있다.
- 워크플로는 매일 한 번, 그리고 직접 실행할 때 돈다.
- 재사용 워크플로가 하는 일
  - 빌드한다: `testClasses`, `docker build`
  - 실행한다: `./gradlew <명령>`, `bash -c`, `docker run`
  - 마지막 200줄과 종료 코드를 보고한다.
  - 입력값은 환경 변수로만 넘겨, 스크립트 안에 끼워 넣지 않는다.
- **결과 규약은 `git bisect run`을 따른다.**
  - 0: 재현 안 됨(코드가 정상 동작)
  - 125: 판단 불가
  - 1~127: 재현됨
  - 128 이상(시그널, 시간 초과로 종료): 판단 불가
  - 빌드 단계 실패: 빌드 실패
  - 개발자에게 이미 익숙한 규약이고, "실패하는 테스트 = 버그가 보인다"와도 맞는다.

### 3. 신뢰: GitHub App 대신 GitHub Actions OIDC 토큰

- 결과는 `POST /reproduction-runs`로 받는다. 인증 수단은 `X-Quno-Attestation` 헤더의 **GitHub Actions OIDC 토큰** 하나뿐이다.
  - 같은 이름의 Authorization 헤더는 기존 JWT 필터와 겹쳐 쓰지 않는다.
- 토큰 검증
  - GitHub JWKS로 서명을 검증한다. JWKS는 `kid`로 캐시하고, 모르는 `kid`가 오면 최대 분당 1회만 다시 가져온다.
  - 발급자(`token.actions.githubusercontent.com`), 대상(`quno`), 만료를 확인한다.
- 토큰에서 저장소, 커밋 sha, 실행 번호·시도, `job_workflow_ref`, `runner_environment`를 읽는다. **요청 본문에서는 읽지 않는다.**
- 이 방식으로 다음을 확인할 수 있다.
  - 이 결과는 그 저장소의 그 커밋에서 실제로 돈 GitHub Actions 작업이 보낸 것이다.
  - `job_workflow_ref`가 Quno의 재사용 워크플로를 가리키면, 종료 코드를 읽고 보고하는 부분은 저장소 소유자가 바꿀 수 없다. 소유자가 정할 수 있는 것은 "무엇을 실행하는가"뿐이고, 그것은 공개 저장소의 그 커밋에 그대로 있어 누구나 확인할 수 있다.
- **GitHub App을 기각한 이유**
  - Quno가 저장소 권한도 비밀값도 갖지 않아도 된다.
  - 사용자가 앱을 설치하는 단계도 없다.
  - 토큰은 작업마다 새로 발급되고 5분 남짓이면 만료된다.
  - Phase 68의 GitHub App은 이슈·PR 연동과 Quno 쪽에서 재실행을 시작하는 데 여전히 필요하다. 다만 재현 결과를 믿는 데에는 필요 없다.
- 결과를 받아들이는 규칙
  - 토큰의 저장소가 캡슐 저장소와 다르면 409다.
  - 캡슐이 커밋에 고정돼 있는데 sha가 다르면 409다.
  - 보고된 실행 방식이나 명령이 캡슐과 다르면 409다.
  - 캡슐이 이미 대체됐으면 409다.
  - 같은 실행 시도는 한 번만 기록한다(토큰은 만료 전까지 재사용될 수 있으므로).
- **신뢰 표시**
  - Quno 워크플로가 아닌 워크플로(직접 작성)로 보낸 결과도 받는다. 다만 "직접 작성한 워크플로"로 표시한다.
  - 자체 러너(`self-hosted`)에서 돈 결과는 "자체 러너"로 표시한다.
  - 둘 다 실행 사실은 증명되지만, 결과 해석이나 실행 환경은 소유자가 바꿀 수 있기 때문이다.

### 4. 기록·집계·로그

- 실행마다 다음을 저장한다(V36 `reproduction_runs`).
  - 결과, 종료 코드, 커밋, 환경
  - 러너 종류, 신뢰 여부, 워크플로 ref, 실행 URL
  - 소요 시간, 로그 꼬리
- **환경**은 워크플로가 보고하는 `ImageOS · java 버전` 문자열이다(예: `ubuntu24 · java 21.0.5`). 증명되지는 않지만, Quno 워크플로라면 그 워크플로가 직접 만든 값이다.
- 질문 화면에는 **환경별 마지막 실행**을 보여 준다. "대상·환경별 마지막 재현 시각"이 이것이다. 최근 실행 10건도 함께 보여 준다.
- 로그
  - 마지막 200줄, 64KB로 자른다.
  - SecretDetector로 비밀값을 `[REDACTED]`로 바꾼 뒤 저장한다(ADR-0081). 가린 개수는 따로 보여 준다.
  - 캡슐마다 최신 20건만 로그를 남긴다. 그보다 오래된 실행은 결과만 남는다.
  - 원본 로그는 GitHub 실행 기록에 있다(보관 기간은 GitHub 설정).

### 5. 이의 제기 → 재실행

- 로그인한 사용자는 결과에 이의를 제기할 수 있다. 사유를 적으면 캡슐에 "재실행 요청됨"이 표시된다.
- 한 번에 하나만 열려 있고, 다음 실행 결과가 오면 닫힌다.
- Quno가 직접 워크플로를 시작하려면 저장소 권한(GitHub App, Phase 68)이 필요하다. 그래서 지금은 요청을 표시만 하고, 매일 도는 실행이나 소유자의 수동 실행이 답한다.
- 알림은 아직 보내지 않는다.

### 6. 비공개 질문(ADR-0085)

- 캡슐과 실행 기록 API는 모두 `/questions/{id}/reproduction` 아래에 있어 공개 범위 게이트를 그대로 따른다.
- 결과 수신 API는 캡슐 id만 받고, 결과 id 외에는 아무것도 돌려주지 않는다.
- Quno가 질문 내용을 어디로 보내는 일은 없다. 실행은 저장소 소유자의 CI에서 일어난다.

## 결과 (Consequences)

- Quno는 코드 실행 비용도 보안 위험도 지지 않고 "재현됨 · 환경 · N시간 전"을 보여 줄 수 있다. 실행 환경은 GitHub이 제공하는 러너 범위로 한정된다. 매트릭스, 이분 탐색, 비공개 저장소는 Phase 81 이후다.
- 공개 저장소만 다룬다. 비공개 저장소의 실행 기록 링크는 다른 사람에게 열리지 않으므로, 막지는 않지만 의미가 줄어든다.
- 재사용 워크플로는 이 저장소의 `main`을 가리킨다. 워크플로를 바꾸면 모든 호출자에게 바로 적용된다. 안정화되면 태그(`reproduce-v1`)로 고정한다. 신뢰 접두사가 `…/reproduce.yml@`이라 태그로 옮겨도 그대로 맞는다.
- 신뢰할 워크플로 접두사, OIDC 발급자, 대상, JWKS 주소는 `quno.runner.oidc.*`로 바꿀 수 있다. 테스트는 JWKS를 로컬 파일로 바꿔, 서명부터 만료까지 실제 검증 경로를 그대로 탄다.
- 검증
  - `ReproductionCapsuleTest`: 종료 코드 규약, 저장소·ref·명령 검사, 이의 제기
  - `ReproductionRunE2ETest`
    - 401: 토큰 없음, 다른 키, 다른 대상, 만료
    - 409: 다른 저장소, 다른 명령, 중복, 대체된 캡슐, 고정 sha 불일치
    - 그 밖: 신뢰·비신뢰 표시, 비밀값 가림, 이의 제기와 해소, 비공개 질문 게이트
  - 브라우저: 로컬 발급자로 서명한 토큰으로 실제 흐름
