# ADR-0089: 검증 등급은 L2까지 먼저, 읽을 때마다 다시 판정, 재현은 보고된 에러와 일치해야, Evidence Card의 자유 텍스트는 `untrusted`로 분리

- 날짜: 2026-11-05
- 상태: 승인됨

## 배경 (Context)

ADR-0070은 질문을 인용할 수 있는 증거 자료로 만들기 위해 L0~L4 검증 등급, Evidence Card, 환경 지문 집계를 정했다. PLAN.md의 대응 항목은 93.6과 Phase 94다.

Phase 80·81(ADR-0087, ADR-0088)로 신뢰할 수 있는 재현 실행이 생겨서 L2까지는 만들 수 있다. 반면 다음은 아직 없다.

- L3의 독립 확인: 사람의 재현 보고(66.1)와 메인테이너 확인(68.3)
- L4의 원인 규명: 업스트림 링크(68)와 이분 탐색(83)

## 결정 (Decision)

### 1. 등급 조건

| 등급 | 조건 |
|---|---|
| L0 미검증 | L1 조건 미충족 |
| L1 구조 충족 | 에러 시그니처, 환경 스냅샷, 기대·실제 동작, 재현 절차, 해결되지 않은 비밀값 없음 |
| L2 재현됨 | L1 + Quno 재사용 워크플로로 GitHub 호스티드 러너에서 실패했고, 그 로그의 에러가 보고된 에러와 일치 |
| L3·L4 | 정의만 유지한다. 위 선행이 생기기 전에는 도달할 수 없고 화면에서도 제안하지 않는다 |

- **기대·실제 동작과 재현 절차는 글에서 찾는다.** 기대·실제는 `기대|예상|expected`와 `실제|actual`, 절차는 캡슐, 코드 블록, 번호 목록, `재현` 같은 표시다. 구조화된 칸을 새로 만드는 것은 기각한다. 작성 화면이 길어지고, 이미 쓰인 질문은 영영 L1이 될 수 없다. 대신 무엇이 빠졌는지 화면에서 알려 준다.
- **ADR-0070의 린트·중복 검사는 L1 조건에서 뺐다.** 정리 제안(ADR-0082)은 권고이고, 같은 에러를 다룬 질문이 있다는 사실이 그 질문의 증거 가치를 낮추지 않는다. 중복은 클러스터로 다룬다.
- **스냅샷과 빌드 파일의 일관성 검사도 하지 않는다.** 스냅샷은 해석된 버전, 스택 지문은 선언된 버전이라 달라도 정상이다. 오탐이 신호보다 많다.

### 2. "같은 실패인가"

- 결과를 받을 때 **가리기 전 로그 꼬리**에서 에러 시그니처를 뽑아, 일방향 키(`signature_hash`, `message_key`)와 예외 클래스만 실행 기록에 남긴다(V38).
- 일치 판정은 **`signature_hash` 또는 `message_key`** 중 하나가 같으면 인정한다. 최소 재현 코드는 원래 앱과 프레임이 다른 것이 정상이므로, 프레임까지 요구하면 L2에 거의 도달할 수 없다. 대신 예외 클래스와 정규화한 메시지는 같아야 한다.
- 비교는 저장 시점이 아니라 **판정할 때** 질문의 최신 판본으로 한다. 질문을 다른 에러로 고쳐 쓰면 L2를 잃는다.
- 직접 작성한 워크플로와 자체 러너의 결과는 L2 근거가 아니다. 저장소 주인이 종료 코드를 바꿀 수 있기 때문이다. 화면에는 계속 표시한다(ADR-0087).

### 3. 판정은 읽을 때, 저장은 순위를 위해서만

- 등급은 저장하지 않고 **읽을 때마다** 순수 함수 `QuestionVerifier`로 판정한다. 규칙이 바뀌거나 시간이 지나도 데이터 이전이 필요 없다(ADR-0081의 마스킹과 같은 이유).
- 검색은 후보마다 판정할 수 없으므로, `question_verifications`에 마지막 판정 결과를 저장한다. 캡슐 변경, 실행 기록, 질문 수정 때 갱신한다.
- 저장값은 순위와 목록 배지에만 쓴다. 한 판본 안에서 비밀값 허용 목록만 바뀌면 다음 갱신까지 어긋날 수 있지만, 상세·카드는 항상 새로 판정하므로 표시는 틀리지 않는다.

### 4. 강등과 표시

등급을 낮추는 것과 경고만 붙이는 것을 나눈다.

| 표시 | 조건 | 등급 |
|---|---|---|
| `NOT_REPRODUCING` | 신뢰 실행의 칸별 최신 결과에 실패가 없고 통과가 있음 | L2 근거가 사라져 L1 이하 |
| `SIGNATURE_MISMATCH` | 신뢰 실행이 실패했지만 다른 에러 | L1 이하 |
| `STALE` | 마지막 재현 후 90일 초과 | L2 유지, 검색 우선순위만 잃음 |
| `DISPUTED` | 이의 제기 후 다음 실행 전 | 유지 |

- 판정 대상은 **활성 캡슐의 칸별 최신 실행**이다. 매트릭스의 한 칸이라도 재현되면 L2다. 나머지 칸은 영향 범위 정보다.
- 오용·버그 아님은 **작성자의 분류**로 저장하고(`classification`), 등급과 별개로 카드에 표시한다. 질문을 지우거나 숨기지 않는다. 모더레이터·메인테이너 판정은 68.3 이후다.

### 5. 노출

- **검색:** 기본 정렬에서 **신선한 L2 이상만** 앞으로 올린다. L0과 L1은 순서를 바꾸지 않는다. L1까지 순위에 넣으면, 양식을 채운 글이 내용과 상관없이 위로 오른다. 투표순 정렬은 사용자가 고른 것이므로 건드리지 않는다.
- **에러 시그니처 매칭:** 강한 일치·약한 일치 순서를 먼저 지키고, 그 안에서 등급순으로 둔다. 다른 에러의 L2보다 같은 에러의 L0이 낫다.
- **목록 카드:** `재현됨 L2` 배지. 상세 패널에는 등급, 경고, 다음 등급 안내(작성자에게만)를 보여 준다. 질문 코치(84)가 생기면 같은 검사를 재사용한다.
- **비공개 질문:** 새 경로는 모두 `/questions/{id}/**` 아래이므로 공개 범위 게이트(ADR-0085)를 따른다. 목록은 기존 viewer 필터를 지난 뒤에 등급만 붙인다.

### 6. Evidence Card

- `GET /questions/{id}/evidence-card`, 스키마 `quno.evidence/1`. MCP 도구는 `get_evidence_card`다.
- Quno가 계산한 구조화 필드: 등급, 경고, 분류, 시그니처 키, 마지막 재현 시각, 재현된·재현 안 된 실행(환경, 버전, 커밋, 실행 URL), 환경 지문, 영향 버전, 주의 사항
- **누구나 쓸 수 있는 글은 `untrusted`에만 둔다**: 제목과 본문 앞 500자. 비밀값은 가린다. 에러 메시지 원문도 구조화 영역에 넣지 않고 키와 예외 클래스만 준다. 메시지 안에 프롬프트 인젝션이 들어갈 수 있기 때문이다(ADR-0070, Phase 96).
- `upstream`은 Phase 68 전까지 빈 배열이다.
- MCP 안내문은 "재현됐다는 뜻이지 해결책이 검증됐다는 뜻이 아니다"라고 명시한다.

### 7. 답변 검증의 정의(94.5)

"검증된 답변"은 **L2 캡슐과 같은 실행 조건에서, 답변의 해결책을 적용한 ref의 실행이 통과하고, 적용 전 ref는 같은 에러로 실패할 때**로 정의한다.

- 통과만 보면 안 된다. 재현 코드가 망가져도 통과하므로, 적용 전 실패가 함께 있어야 한다.
- 구현은 답변과 ref를 잇는 66.3에서 한다. 지금 답변에는 검증 표시가 없고, 카드도 답변을 언급하지 않는다.

### 8. 환경 지문 집계와 러너 레시피(93.6)

- **중복 제거는 별도 테이블 없이 지문으로 묶는다.** 프로필 테이블을 두면 쓰기 경로와 과거 데이터 이관이 늘어난다. 스냅샷의 `fingerprint`는 이미 색인되어 있다.
- `GET /environments`는 환경별 공개 질문 수와 사람이 읽을 이름(`Linux x86_64 · java 21`)을 돌려준다. 공유 집계이므로 공개 질문만 센다(ADR-0085). 이름은 패치 버전을 빼 지문과 단위를 맞춘다.
- **레시피:** 스냅샷에서 가장 가까운 호스티드 러너와 JDK·Node 메이저 버전을 골라 재현 패널의 워크플로 설정을 채운다. 같은 기계가 아니라 가장 가까운 이미지이므로, 맞추지 못한 점(Docker 안, 다른 JDK 벤더 등)을 함께 보여 준다.

## 결과 (Consequences)

- 질문이 "이 실패가 실제로 있다"는 근거를 갖고, 에이전트는 자유 글이 아니라 구조화된 근거를 읽는다.
- L2는 공개 저장소에 재현 코드를 둘 수 있는 질문에서만 가능하다. 처음에는 드물 것이다(ADR-0070이 예상한 "L1은 넓게, L2는 좁게").
- 실제 GitHub Actions 실행으로 L2까지 간 적은 아직 없다. 운영 주소가 생긴 뒤 확인해야 한다.
- 스택 트레이스 없이 메시지만 있는 에러, 시그니처를 뽑을 수 없는 언어는 L1에 도달하지 못한다. 시그니처 추출기의 범위(ADR-0075)를 따른다.
- `question_verifications`가 없는 질문은 순위에서 L2 미만과 같으므로 기존 질문에 이관이 필요 없다.
- 검증
  - `QuestionVerifierTest`: L1 조건, 신뢰 조건, 시그니처 일치·불일치, 강등, 신선도
  - `EnvironmentRecipeTest`: 러너 선택, 메이저 버전, 맞추지 못한 점
  - `ReproductionRunE2ETest`: L0→L1→L2, 다른 에러, 직접 작성한 워크플로, 검색 순서, 카드, 레시피, 집계, 수정 시 강등, 통과 시 강등, 분류
  - MCP `get_evidence_card` 테스트
